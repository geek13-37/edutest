# Edutest, платформа образовательных тестирований

Веб-платформа: администратор регистрирует школы и выдает им коды, учителя
регистрируются по коду школы, создают классы и тесты (вручную или с помощью ИИ),
назначают их классам, ученики проходят тесты, учитель видит результаты и оценки.

- **Backend**: FastAPI + SQLAlchemy + PostgreSQL + Alembic (папка `backend/`)
- **Frontend**: Vite + React + TypeScript + Tailwind + shadcn-подобные компоненты (папка `frontend/`)
- **ИИ**: генерация и доработка вопросов через ChadGPT API (модель `gemini-3.1-flash-lite-preview`)

## Роли

| | Администратор | Учитель | Ученик |
|---|---|---|---|
| Вход | по email + пароль | по email + пароль | по логину + пароль (выдает учитель) |
| Регистрация | заводит другой админ (первый создается при старте backend) | сам, по коду школы от админа | не регистрируется, аккаунт заводит учитель |
| Школы | создает, редактирует, выдает и перевыпускает коды, архивирует и удаляет, выгружает в Excel | своя школа подхватывается по коду при регистрации | нет |
| Учителя | видит всех, создает напрямую, отключает/включает, сбрасывает пароль | нет | нет |
| Классы | нет | создает, заводит учеников, управляет составом | видит свои классы |
| Тесты | нет | гибридный редактор: вопросы вручную + ИИ-генерация/правки | нет |
| Прохождение | нет | нет | по одному вопросу, навигация, автосохранение, таймер |
| Результат | дашборд с динамикой за 12 недель, активные и спящие школы, средний % | полный разбор по вопросам, %, оценка, экспорт в Excel | **только свой % правильных ответов** |

**Админка.** Обзор с графиками (Recharts): новые школы/учителя/прохождения по неделям,
топ активных школ по среднему проценту, список «спящих» школ (0 прохождений за 30 дней).
**Архив школы** вместо удаления: школа скрывается из списков и статистики, её учителя и
ученики не могут войти, данные сохраняются; восстановить можно в один клик, удалить
навсегда — только из архива. **Выгрузка школы**: один xlsx со всеми учителями, классами,
учениками, тестами, назначениями и результатами. **Журнал действий** (`/admin/audit`):
кто и когда создал/изменил/архивировал школу, перевыпустил код, завёл или отключил
учителя, сбросил пароль; записи не редактируются.

Типы вопросов: один вариант, несколько вариантов, верно/неверно, короткий ответ
(ученик вписывает число или слово, автопроверка по совпадению без учёта регистра и пробелов).
Настройки теста: лимит времени, перемешивание вопросов/вариантов, пороги оценок, число попыток и окно доступности на уровне назначения.

**Шаблоны тестов.** При создании теста учитель может выбрать шаблон из встроенного
справочника: «По программе» (Предмет → Класс → Тема, по ФГОС) или «Экзамен»
(ОГЭ / ЕГЭ / ВПР → Предмет → Задание по номеру). Выбор проставляет предмет, класс и
тему тесту (список тестов фильтруется по предмету) и подставляет готовый запрос в
ИИ-панель редактора. Справочник лежит в `backend/app/data/curriculum.json` и
`exam_tasks.json` и расширяется правкой файлов. Списки заданий ОГЭ и ЕГЭ (14 и 15
предметов, ~640 заданий) сверены с каталогом Решу ОГЭ / Решу ЕГЭ (sdamgia.ru).
Задания части 2 экзаменов помечены как требующие ручной проверки: ИИ по ним собирает
закрытую тренировку, а не копию КИМ.

**Школы и коды.** Школу создает администратор (название + город). Для каждой школы
генерируется уникальный код регистрации вида `КАСКАД1569` и уникальный числовой префикс
логинов учеников (напр. `237`), вводить его вручную не нужно. Учитель регистрируется по этому
коду, школа подставляется автоматически, вводить ее вручную не нужно. Код можно перевыпустить
(старый сразу перестает работать). Классы, ученики и тесты жестко привязаны к школе; учителя
одной школы видят и ведут ее классы совместно.

**Классы, ученики, тесты для учителя работают как раньше:**

- **Классы-параллели.** Класс создается как «параллель» (номер + буква) или со своим названием.
  У параллели номер растет каждый год 1 сентября: 6А до 1 сентября после него становится 7А
  (хранится год окончания 11 класса, номер вычисляется от текущей даты).
- **Ученики.** Учитель заводит аккаунты прямо в классе (по одному или списком ФИО). Логин
  `<префикс школы>-<NN>` (`237-07`), пароль `<слово><6 цифр>` (`облако573914`), показывается один раз.
  Кнопки «PDF для печати» (карточки с QR на вход, логином и паролем, пунктир под разрез), «CSV»,
  «Скопировать». Пароль можно
  только сбросить. Существующего ученика школы можно добавить в другой класс поиском по ФИО.
  Любой пользователь может сменить свой пароль (иконка ключа в шапке).

## Быстрый старт (Docker)

```bash
cp .env.example .env
# впишите JWT_SECRET (длинная случайная строка), ADMIN_EMAIL / ADMIN_PASSWORD
# (первый администратор) и CHADGPT_API_KEY
docker compose up -d --build
```

- Фронтенд: http://localhost:5173
- API и Swagger: http://localhost:8000/docs
- Postgres: `localhost:5432`

Миграции применяются автоматически при старте контейнера `backend`, там же из
`ADMIN_EMAIL` / `ADMIN_PASSWORD` создается первый администратор (идемпотентно, при
пустых переменных шаг пропускается). Войдите под ним на `/login`, дальше:
«Школы» → создать школу → скопировать код → отдать учителю.

Создать администратора вручную:

```bash
docker compose run --rm backend python scripts/create_admin.py admin@example.com 'сильный-пароль' 'Иван Админов'
```

### Демо-данные

```bash
docker compose exec backend python scripts/seed.py
```

Создает администратора `admin@edutest.example.com` / `admin12345`, учителя
`teacher@edutest.example.com` / `password123`, школу «МАОУ «СОШ № 3», Северодвинск»
с кодом регистрации, класс 6А с 5 учениками (логины `3-01`..`3-05`, пароли печатаются
в консоль вместе с кодом школы) и назначенный тест.

## Разработка без Docker

```bash
# Postgres
docker compose up -d db

# Backend
cd backend
uv sync
export $(grep -v '^#' ../.env | xargs)      # или задайте переменные вручную
uv run alembic upgrade head
uv run python scripts/create_admin.py        # первый админ из ADMIN_EMAIL / ADMIN_PASSWORD
uv run uvicorn app.main:app --reload

# Frontend (в другом терминале)
cd frontend
npm install
npm run dev        # http://localhost:5173, /api проксируется на :8000
```

### Тесты и миграции

```bash
cd backend
createdb edutest_test    # или: docker compose exec db createdb -U edutest edutest_test
ENV=test uv run pytest
uv run alembic revision --autogenerate -m "описание"
```

## Защита API

- JWT access (30 мин) + refresh (14 дн) с ротацией и отзывом (`refresh_sessions`), argon2 для паролей.
- Регистрация учителей только по коду школы, выданному администратором; ученики через регистрацию
  не заводятся. Вход по email или логину. Отключенный аккаунт (`is_active=false`) и любой
  пользователь школы в архиве (`schools.archived_at`) войти не может; единый ответ 401 при входе.
- Роль `admin` дает доступ к управлению школами, учителями и администраторами; все остальное
  под ролевыми зависимостями.
- Ролевые зависимости + проверка владельца/членства и школы на каждом ресурсе; чужой id → `404`.
- Правильные ответы никогда не уходят ученику (отдельные схемы), оценивание только на сервере.
- Пароли учеников и учителей в открытом виде отдаются только в ответе на создание/сброс, дальше только хеш.
- Серверный контроль попыток, окна доступности и дедлайна таймера.
- Rate limiting (auth, смена пароля, сброс, ИИ, PDF), `extra="forbid"` в схемах, лимит тела запроса, CORS по списку origin, security-заголовки.

## Структура

```
backend/
  app/
    core/         конфиг, безопасность, зависимости, middleware, rate limit
    db/           движок, Base
    models/       SQLAlchemy-модели
    schemas/      Pydantic-схемы (in/out, строгие)
    services/     бизнес-логика (auth, admin, schools, students, classes, tests, ai,
                  assignments, attempts, results, export, analytics, audit, grading,
                  handout: PDF с логинами)
    assets/       шрифты DejaVu для PDF
    data/         справочник шаблонов: curriculum.json + exam_tasks.json
    api/v1/       роутеры (auth, admin, catalog, me, classes, students, tests, assignments, attempts, results)
  alembic/        миграции
  scripts/        create_admin.py + seed.py
  tests/          pytest (сквозной сценарий + auth + admin + школы/классы + IDOR)
frontend/
  src/
    api/          типы + react-query хуки по доменам
    lib/          axios-клиент с авто-refresh, auth-контекст, утилиты
    components/ui/ примитивы UI
    components/layout/ AdminShell (панель админа) + AppShell (учитель/ученик)
    features/     auth, admin (обзор с графиками, школы, учителя, админы, журнал),
                  dashboard, classes, tests (редактор + AI-панель), take, results
docker-compose.yml
```
