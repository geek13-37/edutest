# Edutest, платформа образовательных тестирований

Веб-платформа: администратор регистрирует школы и выдает им коды, учителя
регистрируются по коду школы, создают классы и тесты (вручную или с помощью ИИ),
назначают их классам, ученики проходят тесты, учитель видит результаты и оценки.

- Backend: FastAPI + SQLAlchemy + PostgreSQL + Alembic (папка `backend/`)
- Frontend: Vite + React + TypeScript + Tailwind + shadcn-подобные компоненты (папка `frontend/`)
- ИИ: генерация и доработка вопросов через ChadGPT API (модель `gemini-3.1-flash-lite-preview`)

## Роли

| | Администратор | Учитель | Ученик |
|---|---|---|---|
| Вход | по email и паролю | по email и паролю | по логину и паролю (выдает учитель) |
| Регистрация | заводит другой админ (первый создается при старте backend) | сам, по коду школы от админа | не регистрируется, аккаунт заводит учитель |
| Школы | создает, редактирует, выдает и перевыпускает коды, архивирует и удаляет, выгружает в Excel | своя школа подставляется по коду при регистрации | нет |
| Учителя | видит всех, создает напрямую, отключает/включает, сбрасывает пароль | нет | нет |
| Классы | нет | создает, заводит учеников, управляет составом | видит свои классы |
| Тесты | нет | редактор: вопросы вручную и генерация через ИИ | нет |
| Прохождение | нет | нет | по одному вопросу, навигация, автосохранение, таймер |
| Результат | дашборд с динамикой за 12 недель, активные и спящие школы, средний процент | полный разбор по вопросам, процент, оценка, экспорт в Excel | только свой процент правильных ответов |

Админка. Обзор с графиками (Recharts): новые школы, учителя и прохождения по неделям,
топ активных школ по среднему проценту, список "спящих" школ (0 прохождений за 30 дней).

Типы вопросов: один вариант, несколько вариантов, верно/неверно, короткий ответ
(ученик вписывает число или слово, автопроверка по совпадению без учета регистра и пробелов).
Настройки теста на уровне назначения: лимит времени, перемешивание вопросов и вариантов,
пороги оценок, число попыток, окно доступности.

Шаблоны тестов. При создании теста учитель может выбрать шаблон из встроенного
справочника: "По программе" (предмет, класс, тема, по ФГОС) или "Экзамен"
(ОГЭ, ЕГЭ или ВПР, предмет, задание по номеру). Выбор проставляет предмет, класс и
тему тесту (список тестов фильтруется по предмету) и подставляет готовый запрос в
ИИ-панель редактора. Справочник лежит в `backend/app/data/curriculum.json` и
`exam_tasks.json` и расширяется правкой файлов. Списки заданий ОГЭ и ЕГЭ (14 и 15
предметов, около 640 заданий) сверены с каталогом Решу ОГЭ и Решу ЕГЭ (sdamgia.ru).
Задания части 2 экзаменов помечены как требующие ручной проверки: по ним ИИ собирает
похожую тренировку, а не копию КИМ.

Школы и коды. Школу создает администратор вручную (название и город) либо через
принятие заявки, поданной с главной страницы. Для каждой школы генерируется уникальный
код регистрации вида `каскад1569` и уникальный числовой префикс логинов учеников
(например, `237`), вводить его вручную не нужно. Учитель регистрируется по этому коду,
школа подставляется автоматически. Код можно перевыпустить, старый сразу перестает
работать. Классы, ученики и тесты жестко привязаны к школе; учителя одной школы
совместно видят и ведут ее классы.

Классы, ученики и тесты для учителя работают следующим образом:

- Классы-параллели. Класс создается как "параллель" (номер и буква) или с произвольным
  названием. У параллели номер увеличивается каждый год 1 сентября: 6А после 1 сентября
  становится 7А (хранится год окончания 11 класса, номер вычисляется от текущей даты).
- Ученики. Учитель заводит аккаунты прямо в классе, по одному или списком ФИО. Логин
  имеет вид `<префикс школы>-<номер>` (`237-07`), пароль `<слово><6 цифр>` (`облако573914`)
  и показывается один раз. Доступны кнопки "PDF для печати" (карточки с QR-кодом для входа,
  логином и паролем), "CSV" и "Скопировать". Пароль можно только сбросить и выдать новый.
  Уже существующего ученика школы можно добавить в другой класс поиском по ФИО. Любой
  пользователь может сменить свой пароль через иконку ключа в шапке.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# впишите JWT_SECRET (длинная случайная строка), ADMIN_EMAIL и ADMIN_PASSWORD
# (для первого администратора), а также CHADGPT_API_KEY
docker compose up -d --build
```

- Фронтенд: http://localhost:5173
- API и Swagger: http://localhost:8000/docs
- Postgres: localhost:5432

Миграции применяются автоматически при старте контейнера `backend`, там же из
`ADMIN_EMAIL` и `ADMIN_PASSWORD` создается первый администратор (операция идемпотентна,
при пустых переменных шаг пропускается). После входа под ним на `/login`: раздел "Школы",
создать школу, скопировать код, передать учителю.

Создать администратора вручную:

```bash
docker compose run --rm backend python scripts/create_admin.py admin@example.com 'сильный-пароль' 'Иван Админов'
```

### Демо-данные

```bash
docker compose exec backend python scripts/seed.py
```

Скрипт создает администратора `admin@edutest.example.com` / `admin12345`, учителя
`teacher@edutest.example.com` / `password123`, школу "МАОУ СОШ № 3, Северодвинск"
с кодом регистрации, класс 6А с 5 учениками (логины `3-01`..`3-05`, пароли выводятся
в консоль вместе с кодом школы) и назначенный тест.

## Разработка без Docker

```bash
# Postgres
docker compose up -d db

# Backend
cd backend
uv sync
export $(grep -v '^#' ../.env | xargs)      # или задайте переменные вручную
uv run alembic upgrade head
uv run python scripts/create_admin.py        # первый админ из ADMIN_EMAIL и ADMIN_PASSWORD
uv run uvicorn app.main:app --reload

# Frontend (в отдельном терминале)
cd frontend
npm install
npm run dev        # http://localhost:5173, /api проксируется на :8000
```

### Тесты и миграции

```bash
cd backend
createdb edutest_test    # или: docker compose exec db createdb -U edutest edutest_test
ENV=test uv run pytest
uv run alembic revision --autogenerate -m "описание"
```

## Защита API

- JWT access (30 минут) и refresh (14 дней) с ротацией и отзывом (`refresh_sessions`),
  argon2 для хранения паролей.
- Регистрация учителей только по коду школы, выданному администратором; у учеников
  самостоятельной регистрации нет. Вход по email или логину. Отключенный аккаунт
  (`is_active=false`) и любой пользователь школы в архиве (`schools.archived_at`)
  войти не может, в обоих случаях единый ответ 401.
- Роль `admin` дает доступ к управлению школами, учителями и администраторами; все
  остальное защищено ролевыми зависимостями.
- Ролевые зависимости и проверка владельца, членства и школы на каждом ресурсе;
  при обращении к чужому id ответ 404.
- Правильные ответы никогда не передаются ученику (используются отдельные схемы),
  проверка ответов происходит только на сервере.
- Пароли учеников и учителей в открытом виде отдаются только в ответе на создание
  или сброс, далее хранится только хеш.
- Серверный контроль числа попыток, окна доступности и времени таймера.
- Ограничение частоты запросов (авторизация, смена и сброс пароля, ИИ, PDF),
  `extra="forbid"` в схемах, ограничение размера тела запроса, CORS по списку
  разрешенных источников, стандартные security-заголовки.

## Структура

```
backend/
  app/
    core/         конфиг, безопасность, зависимости, middleware, rate limit
    db/           движок, Base
    models/       SQLAlchemy-модели
    schemas/      Pydantic-схемы (in/out, строгие)
    services/     бизнес-логика (auth, admin, schools, students, classes, tests, ai,
                  assignments, attempts, results, export, analytics, audit, grading,
                  handout: PDF с логинами)
    assets/       шрифты DejaVu для PDF
    data/         справочник шаблонов: curriculum.json + exam_tasks.json
    api/v1/       роутеры (auth, admin, catalog, me, classes, students, tests, assignments, attempts, results)
  alembic/        миграции
  scripts/        create_admin.py + seed.py
  tests/          pytest (сквозной сценарий + auth + admin + школы/классы + IDOR)
frontend/
  src/
    api/          типы + react-query хуки по доменам
    lib/          axios-клиент с авто-refresh, auth-контекст, утилиты
    components/ui/ примитивы UI
    components/layout/ AdminShell (панель админа) + AppShell (учитель/ученик)
    features/     auth, admin (обзор с графиками, школы, учителя, админы, журнал),
                  dashboard, classes, tests (редактор + AI-панель), take, results
docker-compose.yml
```
